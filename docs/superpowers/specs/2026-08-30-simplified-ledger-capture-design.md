# 家庭手账微信小程序：简化录入与资产设计

日期：2026-08-30
状态：已获用户确认，待用户复核文档

## 目标

修复当前真机发现的三个问题，并把录入流程简化为“拍照记账”和“手动记账”两条路径：

1. 首页快捷记账可以稳定打开账目入口。
2. 用户日常录入不再理解或选择账户、转账；系统仍能正确维护总资产。
3. 新家庭拥有可用的默认分类，且分类可在设置中管理。
4. 拍照后由 MiniMax 生成草稿，用户查看总览、修改或确认入账。
5. 导入入口区分拍照、相册、微信文件和 CSV，并保留原件与人工确认安全边界。
6. 导航统一为：首页、账目、AI 聊天、设置。

## 非目标

- 本轮不做多账户选择器、转账 UI、投资、Open Banking 或多币种。
- 不允许 AI 自动确认或自动修改财务记录。
- 不在小程序中暴露 MiniMax、微信 AppSecret、数据库或访问令牌。
- 不把微信小程序的 `chooseMessageFile` 描述成通用 iOS Files/Android 文件管理器。

## 当前根因

- `pages/ledger/index` 是 `tabBar` 页面，但首页使用 `wx.navigateTo`；微信要求切换到 tabBar 页面时使用 `wx.switchTab`。
- 微信登录创建家庭时只创建了家庭和成员，没有内部账本账户和分类；现有小程序也没有账户/分类管理入口，因此选择器为空。
- 当前“文件”按钮调用 `wx.chooseMessageFile`，它选择微信客户端会话中的文件；真机小程序没有通用系统文件选择器。相册图片应使用 `wx.chooseMedia` 的 album 来源。

## 信息架构与导航

四个 tabBar 页面固定为：

- **首页**：总资产、初始资产提示、本月收入、本月支出、拍照记账、手动记账、定期存款摘要、最近收支。
- **账目**：默认本月收入/支出，支持上一月/下一月、年度和自定义起止日期；列表可打开单笔详情。
- **AI 聊天**：只读分析已确认账目，展示分析范围与交易引用。
- **设置**：初始总资产、分类管理、定期存款、家庭成员、周期账单、导出和退出登录。

首页“+”进入一个非 tabBar 的录入选择页，展示两个操作卡片：

1. 拍照记账：拍照或相册选图 → AI 分析 → 总览 → 修改或确认入账。
2. 手动记账：收入/支出、金额、分类、日期、备注 → 保存。

从首页或账目页进入账目 tabBar 必须使用 `switchTab`；所有页面间跳转不得再次对 tabBar 页面使用 `navigateTo`。

## 录入流程

### 拍照记账

照片选择后上传原件，服务端调用 MiniMax 并校验结构化 JSON。总览至少显示金额、日期、商户、分类、备注和 AI 置信度。用户有两个明确按钮：

- **修改信息**：进入可编辑草稿表单。
- **确认入账**：服务端执行重复检查，通过后写入一笔已确认支出/收入。

AI 失败、超时或字段不完整时，原图仍保留，显示“重新分析”和“改为手动录入”。确认前草稿不改变总资产、报表或最近收支。

### 手动记账

手动表单只展示收入/支出、金额、分类、日期和备注。金额保存为整数 NZ 分；时间按 UTC 入库，按 `Pacific/Auckland` 展示。写入携带幂等键，服务端继续做重复候选检查。小程序不展示账户或转账字段。

### 文件入口

导入工作台的按钮为：

- **拍照**：`wx.chooseMedia({ sourceType: ['camera'] })`。
- **相册**：`wx.chooseMedia({ sourceType: ['album'] })`，仅用于本机图片。
- **微信文件**：`wx.chooseMessageFile`，用于从微信会话选择 PDF、CSV 或其他支持文件。
- **CSV**：从微信文件选择 CSV 后进入 ANZ/通用 CSV 预览。

取消选择不提示错误。所有文件继续执行大小限制、签名校验、哈希幂等、AI 草稿和人工确认流程。

## 资产与定期存款

### 隐藏内部账本

每个家庭保留一个内部账户，使用 `Account.systemKey = 'PRIMARY'` 唯一标识。小程序不展示账户概念。新家庭创建时在同一事务中创建它；已有空家庭通过幂等 bootstrap 补齐。现有 Flutter/API 调用仍可传 `accountId`，以保持兼容。

微信创建交易和确认草稿时 `accountId` 可省略，服务端解析为 PRIMARY；如果请求显式传入账户，保留旧 API 语义。

### 总资产公式

```
总资产 = PRIMARY 期初余额
       + 已确认收入
       - 已确认支出
       + 人工余额调整
```

草稿、重复候选、停用分类和未确认 AI 结果均不参与计算。初始资产修改必须写审计事件；不得静默覆盖历史数值。

### 默认分类与管理

空家庭幂等创建以下分类：

- 支出：餐饮、购物、交通、住房、水电网、医疗、教育、娱乐、保险、其他。
- 收入：工资、奖金、利息收入、退款、其他收入。

`Category` 增加 `active` 字段。新录入只显示 active 分类；改名、停用、恢复均有明确操作。已有交易引用的分类只停用，不物理删除。

### 定期存款

新增 `TermDeposit`，字段包括家庭、银行/名称、本金 NZ 分、年利率、开始日期、到期日期、状态（active/matured/closed）、备注、版本号和审计时间。

定期存款本金是总资产的组成部分，不再额外加一次，也不作为支出。记录或编辑定期存款不会生成收入/支出；实际收到利息后，用户使用“利息收入”分类手动记账。到期只触发提醒，不自动入账。

## API 与迁移兼容

- 保持 `/v1/accounts`、`/v1/categories`、`/v1/transactions`、`/v1/drafts`、`/v1/ai/parse-draft` 等现有接口兼容。
- 新增幂等的家庭账本 bootstrap 能力，确保 PRIMARY 账户和默认分类只创建一次。
- `POST /v1/transactions` 和草稿确认接口允许省略 `accountId`，后端解析 PRIMARY；原有显式账户请求不改变。
- 新增分类管理接口的更新/停用/恢复能力；停用不破坏历史交易。
- 新增定期存款的列表、创建、更新、关闭/到期标记接口。
- Prisma 迁移必须为 `Account.systemKey` 和 `Category.active` 提供安全默认值，并新增 `TermDeposit` 表；迁移前后保留数据库备份。
- 所有写接口继续要求幂等键或版本号，并写入审计记录；不能用页面加载隐式覆盖用户数据。

## 错误与安全边界

- 初始化失败：显示“账本设置暂时不可用”和重试，不发送无账户交易。
- AI 解析失败：原件保留，允许重试或转手工；永不自动入账。
- 重复候选：只提供“稍后处理”和“保留两笔”，不自动删除。
- 离线：只读缓存可查看；新增、导入、AI 和设置写操作必须联网。
- 服务器日志只记录状态、耗时、模型 ID 和错误类别，不记录密钥、票据正文或完整财务上下文。
- 定期存款、交易、分类和导出均按家庭权限隔离；聊天记录仍只属于发起成员。

## 验收与测试

自动化测试至少覆盖：

1. 首页快捷入口对 tabBar 使用 `switchTab`，四项导航路径正确。
2. 新家庭和已有空家庭 bootstrap 幂等，重复调用不生成重复账户/分类。
3. 无 `accountId` 的手工交易与草稿确认写入 PRIMARY，旧的显式 `accountId` 请求仍通过。
4. 默认分类、分类新增/改名/停用/恢复，历史引用不被删除。
5. 拍照/相册 → AI 总览 → 修改/确认，以及 AI 失败保留原件。
6. 微信文件、CSV、大小限制、文件签名、哈希幂等和取消选择。
7. 月份、年度、自定义期间查询及单笔详情。
8. 初始资产、收入/支出和定期存款本金不重复计入总资产；利息收入单独计入。
9. MiniMax 模拟响应、超时、限流、Markdown JSON 和空字段容错。
10. PostgreSQL 迁移、家庭隔离、软删除、幂等写入、版本冲突和审计。

微信开发者工具验收：WXML/WXSS/JS 编译无错误、首页“+”可进入选择页、选择器有默认分类、相册/微信文件按钮可打开、控制台无新增 error。真机验收再覆盖真实微信登录、相机权限、相册、真实小票和网络错误。

## 实施边界

按以下顺序实施并逐项验证：

1. 后端 schema/migration、bootstrap、默认分类和无账户字段兼容。
2. 小程序四项导航、录入选择页、switchTab 修复和默认分类展示。
3. 手动记账与拍照 AI 确认流程。
4. 分类管理和定期存款设置页。
5. 账目期间筛选与详情、首页总资产和定期存款摘要。
6. 导入按钮调整、完整自动测试、微信构建和开发者工具回归。

每一步遵循“失败测试 → 最小实现 → 定向测试 → 全量测试 → 构建 → 开发者工具/真机验收 → 小提交”。
