# 家庭手账微信小程序：主题、AI 聊天、拍照来源与底部导航设计规格

日期：2026-08-31
状态：用户已确认设计，待实施计划
范围：微信小程序客户端；生产 AI 502 仅记录部署与验收边界

## 1. 目标

在不改变现有账务模型、AI 权限和人工确认流程的前提下，完成四项体验统一：

1. 设置页提供可持久化的“浅色 / 深色 / 跟随系统”外观选择，并让深色模式覆盖页面、原生顶部区域、自定义底部导航和页面回弹区域。
2. AI 聊天改为微信式左右对话流，键盘出现时输入框始终可见，消息列表同步缩放并定位到最新消息。
3. 拍照记账首屏以相机为主入口，同时明确提供相册和微信聊天图片两个次入口。
4. 四个主页面统一使用五槽视觉的自定义底部导航，中间“记账”按钮作为凸起的高频动作入口。

本规格延续已确认的 Sunlit Ledger 视觉基线：暖象牙白、桉树绿和杏桃色。它描述目标设计和验收标准，不表示这些能力已经在当前代码中完成。

## 2. 不变边界与非目标

- 不新增账户、分类、交易、草稿、导入或确认等账务逻辑；中间“记账”按钮只打开现有记账方式页。
- AI 聊天继续只读，只能分析当前成员有权查看的已确认账目；不得执行写操作、自动入账、自动修改或自动删除财务数据。
- 拍照、相册和聊天图片都进入现有“识别为草稿 → 用户核对 → 人工保存”的链路；选择图片或识别成功本身都不能改变账本。
- 重复候选继续由用户决定，只提供既有的“稍后处理”和“保留两笔”边界。
- 离线仍是“仅查看缓存”；离线时不得发起 AI、拍照识别、导入或其他写操作。
- 不修改 MiniMax Key、微信 AppSecret、数据库连接、token 的存放方式，不把任何服务端秘密放入小程序包。
- 本轮不重新设计账目、报表、设置子页或记账表单，也不引入新的 UI 框架和状态管理依赖。

## 3. 当前基线与目标差异

当前仓库已经具备浅色/深色语义色 token、`darkmode`/`themeLocation` 配置、四项原生 tabBar、只读 AI 消息数据、固定底部输入框、相机入口和聊天文件入口。目标实现需要补齐以下差距：

- 主题目前只随系统媒体查询变化，没有用户偏好、非法存储回退、运行时原生栏同步或页面回弹背景同步。
- 当前底部导航是原生四项 tabBar，没有中间凸起的“记账”动作槽。
- 首页仍有右下角悬浮“＋”，会与新的中间记账入口重复。
- AI 消息容器当前最大宽度约 88%，整条消息本身承担对齐；输入区使用固定定位和固定视口高度，没有键盘高度状态或最新消息锚点。
- 拍照首屏目前只显示“打开相机”；现有聊天文件调用使用 `type: 'all'`，不是本设计要求的聊天图片限定。

这些差异是后续实施计划的输入，不能通过文档阶段修改生产代码来掩盖。

## 4. 总体架构

### 4.1 主题运行层

在现有 `StorageLike` 和 `src/shared/theme` 语义 token 基础上增加一个轻量主题运行层。它只负责四件事：读取和保存主题偏好、把偏好解析为实际浅/深色、向页面与自定义 tabBar 发布变化、同步微信原生界面颜色。

主题值只有：

```text
ThemePreference = light | dark | system
ResolvedTheme   = light | dark
```

偏好使用独立本地键 `family-ledger.theme.v1`。键缺失、JSON/字符串损坏或出现其他值时一律视为 `system`，不显示错误弹窗，也不覆盖其他本地数据。

页面继续使用现有语义颜色，而不是直接散落十六进制颜色。统一页面包装函数在页面加载时注入 `themePreference`、`resolvedTheme`、`themeClass`、`themeBackground` 和 `themePageStyle`，并在卸载时取消订阅。自定义 tabBar 订阅同一主题运行层，禁止另存一份主题状态。

### 4.2 自定义底部导航

`app.json` 保留四个真正的 tab 页面：首页、账目、AI 聊天、设置，并启用微信官方自定义 tabBar。`custom-tab-bar` 在视觉上渲染五个槽位：

```text
首页 | 账目 | [记账] | AI 聊天 | 设置
```

其中四个普通槽使用 `wx.switchTab`；中间“记账”是动作槽，使用 `wx.navigateTo` 打开现有 `/pages/entry/index`。它不是第五个 tab 页面，不持有选中状态，也不复制任何记账业务逻辑。这样进入现有记账流程后仍能正常关闭或返回来源页面。

首页、账目、AI 聊天、设置在各自 `onShow` 同步选中项；从二级页面返回时也必须恢复正确选中状态。中间按钮在四个主页面持续显示，向上凸出导航容器约一半，但点击热区、阴影和安全区不得遮挡左右槽位。

### 4.3 页面背景与原生区域

每个页面的 WXML 首节点使用 `page-meta`，其 `page-style` 绑定当前主题背景。主题运行层同时调用微信原生接口同步：

- `wx.setNavigationBarColor`：顶部导航背景和黑/白状态栏文字。
- `wx.setBackgroundColor`：顶部回弹区、底部回弹区和窗口背景。

页面根容器、自定义 tabBar、弹层和输入区继续使用语义色变量。`page-meta` 与原生接口两条路径必须同时存在：前者覆盖页面级样式与过度滚动可见区域，后者覆盖小程序窗口和原生导航区域，避免深色页面上出现白色断层。

## 5. 主题状态与数据流

### 5.1 启动

```text
读取 family-ledger.theme.v1
  → 校验为 light / dark / system，否则回退 system
  → 若为 system，读取当前系统主题
  → 得到 ResolvedTheme
  → 应用语义 token、page-meta、原生栏和自定义 tabBar
```

`app.json` 现有 `darkmode: true` 和 `themeLocation` 作为启动和系统级兜底保留，但运行时偏好是用户选择后的唯一来源。手动选择浅色或深色时，后续系统主题变化不能覆盖它。

### 5.2 设置页交互

设置页“外观”行改为内联三段式选择器，顺序固定为“浅色 / 深色 / 跟随系统”。它不是跳转项，也不打开底部面板。

用户点击任一段后：

1. 立即更新选中态并解析实际主题。
2. 将合法偏好持久化到 `family-ledger.theme.v1`。
3. 通知当前页面、其他仍存活页面和自定义 tabBar。
4. 同步原生顶部导航、状态栏文字和回弹背景。

本地存储写入失败时，当前会话仍立即应用所选主题，但设置页显示非阻断提示“外观设置未能保存，下次打开可能恢复为跟随系统”。不得因此退出登录或修改账务数据。

### 5.3 系统主题变化

仅当偏好为 `system` 时监听系统主题变化。收到变化后重新计算 `ResolvedTheme` 并执行同一应用流程；偏好仍保存为 `system`。偏好为 `light` 或 `dark` 时忽略系统变化。

### 5.4 颜色与布局约束

- 浅色继续使用象牙白 `#FBF7F0` 背景、桉树绿 `#2F6F64` 主色和杏桃色 `#FF9671` 强调。
- 深色继续使用 `#101714` 背景、`#18221F` 表面、`#74C6B2` 主色和 `#FF9F7D` 强调。
- 收入/支出除颜色外继续带 `+`/`−` 和文字语义。
- 弹层、输入框、卡片、空状态和自定义 tabBar 不得保留硬编码白色背景。
- 四个主页面必须为自定义 tabBar 预留统一底部内边距；普通页面不得被凸起按钮或安全区遮挡。

## 6. AI 聊天设计

### 6.1 对话流与气泡

消息采用“行容器 + 自适应气泡”结构：

- 用户消息行右对齐，气泡为桉树绿底；短句保持短气泡。
- AI 消息行左对齐，气泡使用表面色和杏桃色强调细节；保留“账本助手”身份与只读提示。
- 气泡宽度按内容自然收缩，最大宽度约为可用聊天宽度的 78%；长文本换行，不横向滚动。
- 消息行负责左右对齐，气泡负责内容宽度，不能再用整条 `.message` 的外边距模拟方向。

AI 返回的结构化信息继续来自现有 `answer`、`scope`、`insights` 和 `citations`，在同一个 AI 气泡内展示为紧凑信息块：

- 金额或趋势：展示 insight 的标题、值和单位。
- 异常分析：展示异常标题与 detail，保持只读说明。
- 引用账目：展示商户/名称、格式化金额和可用日期信息。
- 分析范围：作为弱化的范围行，不伪装成可操作筛选器。

这些信息块只使用细分隔线、浅色表面或轻微色块，不能形成大卡片套大卡片。金额、异常和引用仍属于 AI 回答的一部分，点击它们不得触发写账操作。

### 6.2 输入框和键盘

页面不再依赖固定的 `calc(100vh - ...)` 聊天高度。运行时维护：

```text
keyboardHeightPx
composerHeightPx
composerBottomPx
listBottomInsetPx
scrollTarget = chat-end
```

文本域关闭微信默认页面顶起行为，并监听键盘高度变化：

- 键盘关闭：输入框位于自定义 tabBar 与底部安全区上方。
- 键盘打开：输入框底边位于键盘上方并保留小间距；消息列表可视区同步缩小。
- 输入框因多行文字增高时，重新计算列表底部留白，不能覆盖最后一条消息。
- 键盘高度为 0、页面隐藏或卸载时恢复关闭状态并移除监听，避免重复注册。

聊天列表末尾增加稳定锚点 `chat-end`。页面首次恢复历史、新消息加入、AI 回答到达、输入框高度变化和键盘高度变化后，都在视图更新完成后滚动到该锚点。发送失败仍保留用户消息和错误提示，不因滚动重排丢失上下文。

## 7. 拍照记账来源设计

拍照记账首屏采用明确的主次层级：

- 主按钮“打开相机”：`wx.chooseMedia({ count: 1, mediaType: ['image'], sourceType: ['camera'] })`。
- 次按钮“从相册选择”：`wx.chooseMedia({ count: 1, mediaType: ['image'], sourceType: ['album'] })`。
- 次按钮“从聊天选择”：`wx.chooseMessageFile({ count: 1, type: 'image' })`。

两个次按钮在主按钮下方等宽并列；窄屏仍保持可点击文字完整，必要时允许按钮文字换行，不裁切。“从聊天选择”明确指微信会话中的图片，不描述为系统文件管理器。

三种来源只负责返回统一的图片文件描述，之后复用现有读取字节、20 MB 限制、文件签名检查、哈希幂等、AI 分析、原件保留、草稿编辑和人工确认流程。账单文件分支和导入工作台现有 PDF/CSV 能力不因本页三种图片来源而扩大或缩减。

用户主动取消相机、相册或聊天图片选择时：保留当前页面和已有状态，不显示错误、不弹 toast、不自动切换到手工录入。只有真实选择、读取、校验、上传或 AI 分析失败才进入错误状态；已选文件在能够取得文件描述后必须保留，以便重试或转手工录入。

## 8. 自定义导航细节

- 五槽从左到右固定为：首页、账目、记账、AI 聊天、设置。
- 普通槽显示图标和文字；选中态使用桉树绿，未选中态使用次要文字色。
- 中间按钮使用杏桃色或与现有拍照入口一致的强调面，形状与其他槽明显不同，向上凸出约一半，并保留“记账”文字标签。
- 自定义 tabBar 的背景、上边线、阴影和安全区填充全部响应主题。
- 中间按钮点击后始终打开现有记账方式页；连续快速点击不得生成多个重叠页面实例。
- 首页右下角旧悬浮“＋”的 WXML、样式和只服务于该按钮的处理器一并移除，避免双入口和遮挡。
- 二级页面不强行显示 tabBar；从记账、详情、设置子页返回时恢复来源主页面及其正确选中态。

## 9. 错误处理

| 场景 | 用户可见行为 | 状态与安全要求 |
| --- | --- | --- |
| 主题偏好缺失或非法 | 静默使用“跟随系统” | 不影响登录、缓存或账务数据 |
| 主题存储失败 | 当前会话立即切换，显示非阻断提示 | 不伪造已持久化状态 |
| 原生颜色接口失败或旧基础库不支持 | 页面语义色继续生效 | 记录非敏感诊断；不阻断页面 |
| 图片选择取消 | 留在当前页，无错误提示 | 不清空已有草稿或文件 |
| 图片读取/校验失败 | 显示可重试错误 | 不调用 AI，不写账 |
| 上传或 AI 分析失败 | 保留原件，提供重试或手工录入 | 不自动确认、不改变报表或余额 |
| AI 聊天离线 | 提示需要联网 | 不发请求，不伪造回答 |
| AI 超时/401/409/其他失败 | 延续现有分类提示与登录跳转规则 | 聊天记录和只读边界不变 |
| 键盘事件异常或高度为 0 | 回退到关闭键盘布局 | 输入框仍位于 tabBar/安全区上方 |

## 10. 生产 AI 502 的已知根因与部署边界

生产 AI 502 已确认不是本轮聊天 UI 引起。空账本场景下，MiniMax 可能返回：

```json
{"scope":{"from":null,"to":null}}
```

线上 API 仍按 `scope.from`/`scope.to` 必须为字符串的旧校验处理，因此把本可回答的结果转换为 Bad Gateway。共享 API 本地工作树已有修复和回归测试：MiniMax 返回的 null/非法 scope 被视为“未提供”，`AiChatService` 改用服务端已计算、可信的报表期间 `context.scope`；回答、洞察和已授权交易引用仍按原有规则校验。

该修复尚未部署到线上 API 容器，因此文档或小程序前端完成不能被表述为生产 502 已修复。重建并发布 VPS API 容器属于独立的线上变更，必须先获得用户单独授权。获权后的验收顺序为：

1. 仅重建和部署目标 API 服务，不顺带修改数据库或其他 Docker 栈。
2. 核对容器启动、健康检查和非敏感日志。
3. 使用有效登录态分别验证空账本和有账目家庭的 `/v1/ai/chat`，确认返回合法字符串 scope、只读回答和授权引用。
4. 再在微信开发者工具和真机完成 AI 多轮对话、键盘和消息展示验收。

未取得授权前，不执行 VPS 重建、部署、重启或凭据变更。

## 11. 自动化测试

### 11.1 主题

- `light`、`dark`、`system` 三种偏好都能读取、保存并立即应用。
- 缺失、损坏和未知偏好都回退到 `system`。
- 仅 `system` 响应系统主题变化；手动浅色/深色保持不变。
- 页面包装函数、自定义 tabBar 和原生颜色接口收到同一个 `ResolvedTheme`。
- 设置页三段式顺序、选中态和失败提示符合规格。
- WXML 的 `page-meta` 位于页面首节点，页面背景、顶部/底部回弹色和状态栏文字参数正确。

### 11.2 自定义 tabBar

- `app.json` 启用 custom tabBar，四个真实 tab 路径保持首页、账目、AI 聊天、设置。
- 自定义组件渲染五个视觉槽；普通槽调用 `switchTab`，中间槽调用一次 `navigateTo('/pages/entry/index')`。
- 四个主页面的 `onShow` 选中态正确；中心按钮永不显示为选中 tab。
- 首页不再渲染旧悬浮“＋”，底部安全区和内容内边距不遮挡操作。

### 11.3 AI 聊天与键盘

- 用户消息右对齐、AI 消息左对齐；短消息气泡不撑满，最大宽度约 78%。
- scope、金额/趋势 insight、异常 detail 和交易引用都位于 AI 气泡内部并使用现有结构化数据。
- 键盘高度变化、输入框多行增高、页面恢复历史和新消息到达都会更新列表底部留白并滚到 `chat-end`。
- 页面卸载会解除键盘监听；重复进入页面不会重复处理一次事件。
- 离线、超时、401、409、删除聊天和本地缓存清理的现有测试继续通过。

### 11.4 拍照来源

- 相机、相册和聊天图片分别断言 `sourceType: ['camera']`、`sourceType: ['album']`、`type: 'image'`。
- 三种取消回调都不设置错误、不清空状态、不调用分析。
- 三种成功回调进入同一文件读取和分析路径。
- 真实读取失败、20 MB 超限、签名不符、上传失败、AI 失败、重试、原件保留和人工确认边界继续覆盖。

### 11.5 回归命令

本地实施完成后至少运行：

```powershell

npm run typecheck
npm run build:wechat
git diff --check
```

自动化只证明本地代码行为，不能替代微信客户端、系统主题、键盘、权限或线上 API 的真实验收。

## 12. 微信开发者工具与真机验收

分别在浅色、深色、跟随系统三种偏好下检查：

1. 设置页切换立即生效，重新打开小程序后偏好仍在；跟随系统能响应系统切换。
2. 页面内容、原生顶部导航、状态栏文字、自定义 tabBar、弹层、底部安全区以及向上/向下过度滚动都没有白色断层。
3. 四个主页面持续显示五槽视觉导航，选中态正确；中间按钮凸出约一半并只打开一个现有记账方式页。
4. 首页不再出现右下角旧“＋”。
5. AI 短消息保持短气泡，长消息不溢出；金额、异常、范围和引用在 AI 气泡内清晰可读。
6. 键盘打开、收起、切换输入法和输入多行文字时，输入框不被遮挡，最新消息始终可见。
7. 相机、相册和微信聊天图片入口分别打开正确来源；取消无报错；真实失败可重试且不会自动入账。
8. 经用户授权部署 API 后，使用真实登录态验证生产 AI 不再因 null scope 返回 502，并确认回答仍只读、引用仍受家庭权限约束。

## 13. 完成定义

只有同时满足以下条件，客户端实现才可称为本地完成：

- 主题、聊天、拍照来源、自定义 tabBar 和首页旧入口均符合本规格。
- 所有相关定向测试、全量 Jest、TypeScript、构建和 `git diff --check` 通过。
- 微信开发者工具完成浅/深色、回弹背景、导航、键盘和三种图片来源验收。

真机权限、真实系统键盘差异和生产 AI 属于单列外部验收。生产 502 只有在用户授权部署、线上带登录态请求通过且真机验证完成后，才可标记为已解决。
