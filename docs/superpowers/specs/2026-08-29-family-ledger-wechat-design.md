# 家庭手账微信小程序设计规格

## 1. 目标与已确认选择

将现有家庭手账扩展为微信原生小程序客户端。小程序和 iOS 客户端共享同一个 NestJS API、同一个 PostgreSQL 数据库和同一套家庭账务规则。

已确认的选择：

- 前端：微信原生小程序 + TypeScript、WXML、WXSS。
- 仓库：独立前端仓库 `home-financial-assistance-wechat`；不复制 API 或数据库。
- 货币与统计：继续使用 NZD、整数 NZ 分、`Pacific/Auckland` 展示和统计。
- 登录：`wx.login`，由服务端换取微信身份；首次无邀请码时创建“我的家庭”并成为 owner，有邀请码时加入已有家庭。
- AppID：当前没有，先保留环境变量和 Mock 登录模式，正式环境再启用微信身份交换。
- AI 聊天：第一版使用普通请求返回完整回答；保留后端流式接口，不把分块流式作为小程序 MVP 阻塞项。
- 视觉与交互：采用已确认的 A 方案——青绿色家庭驾驶舱、单页快速记账、单页导入工作台、单项草稿复核、摘要优先报表、快捷问题 + 交易引用的 AI 聊天。

## 2. 非目标

第一版不做：离线写入、AI 自动入账、Open Banking、投资/房产、多币种、预算、公开发布、复制数据库、在前端保存 AppSecret。

## 3. 仓库与组件边界

```text
home-financial-assistance-wechat/
├─ src/
│  ├─ api/             # /v1 API client、错误映射、token 刷新
│  ├─ auth/            # wx.login、会话和首次登录流程
│  ├─ domain/          # 金额/周期/展示模型，不能直接写数据库
│  ├─ mocks/           # 无 AppID 时的登录和 API mock
│  ├─ storage/         # wx.setStorageSync 封装和只读缓存
│  └─ shared/          # 类型、格式化、本地化文案
├─ pages/
│  ├─ dashboard/       # 家庭驾驶舱
│  ├─ ledger/          # 交易列表和单页记账
│  ├─ imports/         # 图片、PDF、CSV 导入工作台
│  ├─ drafts/          # 单项草稿和重复候选复核
│  ├─ reports/         # 月/季/年摘要和下钻
│  ├─ ai/              # 只读 AI 聊天
│  ├─ recurring/       # 周期账单
│  ├─ household/       # 成员和邀请码
│  └─ more/             # 导出、设置、退出
├─ components/         # 金额卡、周期切换、交易行、确认面板
├─ tests/              # TypeScript 单元和 API contract tests
└─ docs/
```

每个页面只负责展示和用户交互；网络、token、缓存、金额格式化和错误分类由共享模块负责。小程序页面不直接读写 Prisma 或数据库。

## 4. 微信认证与后端契约

### 4.1 数据模型

现有 API 仓库增加 `WechatIdentity`：

```text
WechatIdentity {
  id         String   @id @default(uuid())
  userId     String
  openId     String   @unique
  unionId    String?
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt
  user       User     @relation(...)
}
```

`User` 增加身份反向关系；家庭、成员、账户、交易、草稿、附件和审计表保持原有结构。

### 4.2 登录流程

小程序调用 `wx.login()`，向 `POST /v1/auth/wechat/login` 发送：

```json
{
  "code": "temporary-code",
  "inviteCode": "optional-invite",
  "householdName": "optional-name"
}
```

服务端行为：

1. 正式模式使用 `WECHAT_APP_ID`/`WECHAT_APP_SECRET` 调用微信 `jscode2session`；AppSecret 只在服务端环境存在。
2. 已绑定 `openId` 时签发现有 access/refresh token。
3. 新身份带邀请码时创建 User 并加入邀请对应的家庭。
4. 新身份无邀请码时创建 User、家庭和 owner membership，家庭名称优先使用用户输入，否则为“我的家庭”。
5. 邀请码仍然一次性、过期可验证、数据库只保存哈希。

小程序把 token 存入微信本地存储，仅在请求头中发送 access token；401 时尝试一次 refresh，失败则清除会话并返回登录页。Mock 模式使用固定测试身份，禁止在生产配置启用。

## 5. 页面与交互

### 5.1 底部导航

固定为“首页 / 账目 / 报表 / 更多”。首页右下角浮动“+”进入单页记账，避免把高频操作藏在更多页。

### 5.2 首页驾驶舱

按顺序展示：净资产、本月/本季/本年切换、收入/支出摘要、待确认草稿、重复候选、周期账单提醒和最近交易。缓存读取失败时展示上次数据及“缓存数据”提示；不允许以缓存状态执行写操作。

### 5.3 单页记账

顶部使用收入/支出/转账分段选择；金额突出显示，下面依次选择账户、分类、日期、备注和拍照/附件。保存时生成客户端幂等键并调用 API。服务端返回重复候选时弹出原交易日期、金额和原因，只允许“稍后处理”或明确“保留两笔”。

### 5.4 单页导入工作台

同屏提供拍照、文件和 CSV 入口。图片/PDF/CSV 先校验大小与类型，再上传到 API：

```text
选择文件 → 解析/AI 预览 → 生成草稿 → 单项复核 → 选择账户 → 查重 → 人工确认
```

原件加密保存；AI 失败保留原件并允许重试或手填。草稿确认前不进入余额和报表。

### 5.5 草稿与重复项

默认单项复核：显示来源、原件、AI 置信度、金额、商户、账户和分类。重复项紧贴草稿显示，支持“稍后处理”“确认保留两笔”和返回修改。任何合并或保留动作都必须有服务端审计事件。

### 5.6 报表

摘要优先：周期切换、净现金流、收入/支出、分类列表和账户列表。点击分类或账户进入交易下钻，筛选条件写入页面状态并可返回。数据仅来自已确认且未软删除的交易。

### 5.7 AI 聊天

提供“本月花最多的分类”“找出异常支出”“比较本季与上季”等快捷问题。每个回答展示统计范围和交易引用；聊天记录只对发起成员可见并可删除。客户端使用普通 JSON 请求，不支持离线发送，不允许展示为可执行的记账操作。

### 5.8 更多

家庭成员/邀请码、周期账单、CSV/JSON 导出、设置和退出登录集中在此。owner 才看到生成邀请码和移除成员操作；邀请码通过一次性领取和过期自动失效。

## 6. API、缓存与错误处理

- API 根地址通过 `src/shared/config` 注入，开发、测试和生产配置分离。
- 所有写请求携带客户端幂等键或版本号；客户端不得静默重试可能产生账务变化的请求超过一次。
- `401`：刷新一次 token；`409`：展示版本冲突或重复候选；`413`：提示文件过大；`422`：展示字段校验；网络超时：提示“未写入，请检查账目后重试”。
- 首页摘要、报表和最近交易使用带时间戳的只读缓存；草稿、导入、成员和 AI 不在离线状态伪造结果。
- 退出登录清除 access/refresh token 和用户私有 AI 缓存，不清除家庭账本服务器数据。

## 7. 安全与隐私

- AppSecret、MiniMax Key、数据库连接串绝不进入小程序代码、构建产物或日志。
- API 继续执行家庭归属、成员角色、附件下载和审计校验；前端隐藏按钮不能替代服务端授权。
- 文件使用现有加密附件边界；小程序上传前限制图片/PDF/CSV 类型和 20 MB 大小。
- 日志不记录原始票据正文、AI 私聊正文、token 或文件内容。
- Mock 登录仅用于开发构建，生产构建必须拒绝 Mock 开关。

## 8. 测试与验收

### 自动化

- TypeScript 单元测试：金额 NZ 分格式化、周期边界、会话刷新、幂等键、错误映射和缓存过期。
- API contract tests：登录、首页摘要、交易写入、导入草稿、重复候选、报表、AI 和导出。
- Mock 页面测试：登录、单页记账、票据导入、单项复核、报表下钻和 AI 快捷问题。

### 微信开发者工具冒烟

1. Mock 登录创建“我的家庭”。
2. 创建账户、分类和收入/支出/转账。
3. 重复点击保存只产生一笔交易。
4. 选择图片/CSV 生成草稿并确认一笔。
5. 命中重复候选后选择“稍后处理”和“保留两笔”。
6. 月/季/年报表和分类下钻可返回。
7. AI 回答显示统计范围和交易引用。
8. owner 生成邀请码，另一 Mock 用户使用邀请码加入。
9. 断网时可查看缓存，写操作明确失败且不改变账本。

正式验收仍需要微信 AppID、合法服务器域名、真实 MiniMax Key、真实 ANZ 样本和 HTTPS 环境；这些不在当前无 AppID 的本地设计阶段伪造。

## 9. 分阶段实现

1. 初始化小程序原生 TypeScript 工程、Mock、lint/test 和 API client。
2. 接入微信登录契约与现有 API 的身份绑定迁移。
3. 实现驾驶舱、缓存、底部导航和单页记账。
4. 实现图片/PDF/CSV 导入、草稿单项复核与重复候选交互。
5. 实现报表、周期账单、家庭管理和导出入口。
6. 实现只读 AI 聊天、错误处理、安全检查和开发者工具冒烟。
7. 在有 AppID/服务器域名后完成真实微信登录、HTTPS、上传域名和真机验收。

## 10. 设计验收标准

- 新仓库不会复制 API/数据库代码；所有账务写入都经现有 API。
- 首次微信登录能明确走“创建家庭”或“邀请码加入”之一，不产生无归属用户。
- 首页和记账遵循青绿色 A 方案；导入、复核、报表和 AI 交互与已确认原型一致。
- AI、票据和重复项都保留人工确认门槛。
- 没有 AppID 时可运行 Mock 流程，但生产构建不会误启用 Mock。
- 所有本地可运行测试通过后，才进入微信开发者工具和真实环境验收。
