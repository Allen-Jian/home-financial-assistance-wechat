# Mock 验收流程

这份流程用于没有微信 AppID 的开发阶段。它验证页面模型、现有 API 和共享 PostgreSQL 数据库之间的完整业务路径，不代表真实微信登录或生产部署已经通过。

## DevTools 准备

1. 在微信开发者工具中导入本仓库，选择 `project.config.json`。
2. 在本机未跟踪的 `project.private.config.json` 或工具环境中设置 API 地址；不要把 AppSecret、MiniMax Key、数据库连接串或 token 写入仓库。
3. API 使用一个隔离的测试数据库，并配置：

   ```text
   WECHAT_MOCK_MODE=true
   WECHAT_MOCK_OPENID=dev-openid-1
   ```

4. 确认 API 已完成 Prisma migration，`/v1/health` 返回健康状态；小程序端只使用 API，不直接访问 PostgreSQL。

## 通过标准

1. 首次 Mock 登录不填邀请码，家庭名称留空，出现“我的家庭”，当前用户角色为 `owner`。
2. 创建一个资产账户（例如“日常账户”）和收入/支出分类，录入一笔 NZD 账目；金额以整数 NZ 分保存。
3. 使用同一个 `idempotencyKey` 重复提交同一笔账目，API 不产生第二笔。
4. 在“导入”选择脱敏 ANZ CSV，预览行后 staging；同一个文件再次 staging 显示 reused，不重复上传原件。
5. 在“导入”分别拍照/选择脱敏 PDF 和输入“昨天超市花了 18.90”，确认两者都经过 AI 预览后生成待确认草稿；AI 失败时原件仍保留并可重试或手工录入。
6. 在“待确认”逐项检查商户、金额、日期、建议分类和账户；确认前驾驶舱余额不变，确认成功后余额才变化。
7. 用相同日期窗口、金额和方向制造一笔交易，检查重复候选；选择“稍后处理”保留候选，选择“保留两笔”才发送 `allowDuplicate=true`。
8. 分别查看月、季、年报表，确认范围使用 `Pacific/Auckland` 的本地日历边界；分类下钻不改变当前范围。
9. 打开 AI 页面，依次提问：
   - `本月花最多的分类？`
   - `找出异常支出`
   - `比较本季与上季`

   回答只能引用已确认交易并显示范围/交易引用；AI 页面不提供 SQL、工具名或修改按钮。
10. 继续追问“那上个月呢？”，确认请求复用了同一个 conversationId；刷新页面后历史仍可恢复。点击“删除聊天记录”，确认服务端和本地记录都被清除。
11. 返回驾驶舱，确认“本月关注”只读卡片可显示；切换系统浅色/暗夜模式，确认 J 配色自动切换且没有手动主题开关。
12. owner 创建 1–30 天邀请码并复制；将 Mock openid 改为 `dev-openid-2` 后重新登录，使用邀请码加入同一家庭，角色为 `member`。
13. 断开网络后刷新驾驶舱，若有新鲜缓存显示“缓存数据”；尝试新增、编辑、导入或 AI 操作必须被拒绝，不能显示成功。

## 失败记录

记录失败步骤、请求路径、脱敏响应、客户端页面和修复提交。不要粘贴完整小票、银行账号、refresh token 或 AI 原文到 issue/日志。
